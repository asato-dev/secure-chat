# 🔐 SecureChat

エンドツーエンド暗号化（E2EE）対応のリアルタイムチャットアプリケーション

---

## 概要

SecureChat は、**サーバー管理者でもメッセージを読むことができない**エンドツーエンド暗号化を実装したチャットアプリです。メッセージの暗号化・復号はすべてブラウザ側で行われ、サーバーは暗号化済みデータの保存・転送のみを担当します。

---

## 主な機能

- **エンドツーエンド暗号化（E2EE）** — メッセージはサーバーに届く前にブラウザで暗号化される
- **ユーザー認証** — bcrypt によるパスワードハッシュ化
- **秘密鍵バックアップ** — PBKDF2 によりパスワードから派生した鍵で秘密鍵を暗号化しサーバーに保存。機種変更・キャッシュ削除後も復元可能
- **リアルタイムチャット** — ポーリングによる新着メッセージの自動取得
- **アカウント管理** — ユーザー名・パスワードの変更、アカウント削除
- **XSS対策** — ユーザー入力のエスケープ処理
- **セッション管理** — 有効期限付きセッション（2時間）

## 暗号化の仕組み

### ハイブリッド暗号方式

```
登録時（1回のみ）:
  ① ブラウザで RSA-2048 鍵ペアを生成
  ② 秘密鍵 → localStorage に保存 + PBKDF2でバックアップ（サーバーは中身を読めない）
  ③ 公開鍵 → サーバーに登録

メッセージ送信時:
  ① AES-256-GCM 鍵（32byte）をランダム生成（送信ごとに使い捨て）
  ② メッセージを AES-GCM で暗号化（改ざん検知付き）
  ③ 同じ AES 鍵を受信者の RSA 公開鍵で暗号化（encrypted_key）
  ④ 同じ AES 鍵を送信者自身の RSA 公開鍵でも暗号化（encrypted_key_for_sender）
  ⑤ 暗号化済みデータをサーバーに送信

秘密鍵バックアップ（PBKDF2）:
  ① ログインパスワードから PBKDF2（10万回反復）で AES 鍵を派生
  ② その AES 鍵で RSA 秘密鍵を AES-GCM 暗号化
  ③ 暗号化済み秘密鍵をサーバーに保存（Salt + IV + 暗号文をまとめてBase64）
  ④ 機種変更後のログイン時にパスワードから同じ AES 鍵を再現して復号・復元
```

サーバーが保持するのは暗号文のみであり、AES 鍵も RSA で暗号化された状態で保存されます。秘密鍵バックアップについても、サーバーはパスワードも派生鍵も知らないため中身を読めません。

## v1 からの改善点

| 項目 | v1 | v2（本バージョン） |
|------|----|--------------------|
| メッセージ暗号化モード | AES-256-CBC | AES-256-GCM（改ざん検知付き） |
| 秘密鍵の保存先 | localStorage のみ | localStorage + PBKDF2 バックアップ |
| 機種変更後の復元 | 不可（過去メッセージ閲覧不可） | パスワードで自動復元 |
| 改ざん検知 | なし | GCM 認証タグにより検知 |

### AES-CBC → AES-GCM に変更した理由

AES-CBC はメッセージの暗号化のみを行い、改ざん検知機能を持ちません。万が一 DB への侵入が起きた場合、暗号文を書き換えられてもブラウザ側で気づかず復号してしまいます。AES-GCM は暗号化と同時に認証タグを生成し、復号前に改ざんを検知して処理を中断します。TLS 1.3 でも CBC が廃止され GCM が採用されている現代の標準です。

### 既知の制約と今後の課題

- **前方秘匿性がない** — RSA 鍵は登録時に1回のみ生成・使い続けるため、将来的に秘密鍵が漏洩した場合、過去のメッセージが復号される可能性がある。Signal プロトコルの Double Ratchet を導入することで解決できる
- **量子コンピュータ耐性がない** — RSA は将来の量子コンピュータによる素因数分解攻撃に対して脆弱。NIST が 2024 年に標準化した ML-KEM（CRYSTALS-Kyber）への移行が今後の課題

## セットアップ

### 必要環境

- Python 3.10 以上
- PostgreSQL

### インストール

```bash
# リポジトリをクローン
git clone https://github.com/asato-div/securechat.git
cd securechat

# 依存関係をインストール
pip install -r requirements.txt
```

### 環境変数の設定

`.env` ファイルをプロジェクトルートに作成します。

```env
DATABASE_URL=postgresql://user:password@localhost:5432/securechat
SECRET_KEY=your-secret-key-here
```

### 起動

```bash
# 開発環境
python app.py

# 本番環境（Gunicorn）
gunicorn app:app --bind 0.0.0.0:8080
```

ブラウザで `http://localhost:8080` にアクセス。

## セキュリティ上の考慮点

- **秘密鍵はサーバーに平文で送信されない** — PBKDF2 で暗号化した状態でのみサーバーに保存。サーバーはパスワードも復号鍵も知らない
- **サーバーはメッセージを復号できない** — 暗号化済みデータのみを保管
- **改ざん検知** — AES-GCM の認証タグにより、DB 侵入後の暗号文書き換えをブラウザ側で検知可能
- **SQLインジェクション対策** — プレースホルダを使用したパラメータ化クエリ
- **XSS対策** — ユーザー入力を DOM 挿入前にエスケープ
- **パスワードの安全な保存** — bcrypt によるハッシュ化（ソルト付き）
- **セッション有効期限** — 2時間で自動失効
- **入力バリデーション** — ユーザー名は英数字・アンダースコアのみ許可
- **ブルートフォース対策** — PBKDF2 の 10 万回反復により、パスワード総当たりの計算コストを大幅に増加
